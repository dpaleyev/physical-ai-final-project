# Фактическая валидация

Дата: 2026-09-29. Хост: Linux x86_64, Python 3.12.3, 24 логических CPU, 61 GiB RAM.
Рабочий NVIDIA-драйвер недоступен. MuJoCo 3.3.7, PyTorch 2.7.1+cpu; рендер OSMesa.
Полный список версий — `requirements-lock.txt`.

Репозиторий опубликован приватно под `dpaleyev`. [GitHub Actions](https://github.com/dpaleyev/physical-ai-final-project/actions/runs/36494075711)
успешно проверил код новых задач в commit `21f61af`; в черновике релиза приложен студенческий ZIP.

## Подтверждено

- Все восемь сохранённых XML компилируются после переноса вместе с assets.
  В каждом есть `home` keyframe с настроенной позой руки и открытым захватом.
- 29 автоматических тестов проходят локально и в Docker с чистой установкой
  зависимостей. Запуск Docker-тестов выполнялся без сети. Лог — `evidence/test_results.txt`.
- Физический probe выполнил **24/24 base-эпизода** (seeds 0, 1, 7 на каждую из 8 пар)
  и **24/24 advanced-эпизода** (три варианта на пару). Проверены обе цветовые цели
  в base и advanced. Перенос занял 255–287 шагов; каждый уложился в 1000
  управляющих шагов. Подробные позиции, цели, heights и steps —
  `evidence/physical_probes.json`.
- Пробой используются настоящие контакты, приводы и трение; нет weld-приклеивания
  или переноса предметов через запись qpos во время эпизода.
- Сквозной smoke: настоящие PPO-обновления для 8 пар → сбор эпизодов → обучение
  трёх BC-вариантов → TorchScript → приватная оценка. **64/64 конфигурации
  оценщика без технической ошибки**. Доказательства — `evidence/integration_smoke.json`.
- PPO resume проверен с изменением размера rollout, seed и числа сред (1 → 2),
  а также восстановлением согласованного gamma из checkpoint с другим значением.
- Экспорт исключает приватные файлы и историю; в студенческом экспорте отдельно
  прошли 22 публичных теста. Финальный Docker-образ проверен без bind-mount и сети.
- Независимое ревью выявило три ошибки (ориентации MJCF, параметры resume,
  изоляция ошибки отсутствующего артефакта). Для каждой воспроизведено падение
  regression-теста; исправления прошли полную suite.

## Изменения после пилота

Две многоэтапные задачи заменены на `cup_distractor` и `color_match` по запросу
заказчика. Для первой advanced смещает стартовые положения двух кружек; для второй
использует новую палитру и случайное назначение цветов двум тарелкам. Студенческая
часть этих правил не раскрывает. Все сцены, матрицы сдачи, изображения и проверки
перегенерированы.

Проверка награды выявила, что старая формула предпочитала бесконечно держать кружку
около цели, вместо завершения. В стадии `place` теперь используется согласованный
с PPO discounted potential shaping, нулевой потенциал при истинном terminal и
терминальный бонус 100. Time-limit truncation сохраняет потенциал для bootstrapping.
Regression из одного физически достигнутого состояния: раньше return ожидания
18.8447 против 18.7101 у завершения; теперь −23.2470 против 46.0205.
Доказательство — `evidence/reward_regression.json`; тест защищает это сравнение.
Resume принудительно согласует gamma модели и rollout buffer с `env.DISCOUNT`.

## Что эти проверки не доказывают

Smoke использует 64 PPO-шага на пару, четыре перехода в демонстрации, одну эпоху
BC и два шага при проверке интерфейса оценщика. Эти данные намеренно включают
неуспешные эпизоды. Полученные веса не являются готовыми экспертами или учебными
результатами и не включаются в студенческую поставку.

Отдельный PPO-пилот на UR5e/cup_plate выполнил 32 768 шагов стадии `reach`, примерно
2 200 transitions/s на восьми CPU-процессах. На трёх проверочных эпизодах полная
задача не решена (0/3). Это короткая проверка обучения, не оценка финального метода.
Метаданные и результаты — `evidence/ppo_short_pilot.json`.

Продолженный place-пилот со **старой наградой v1** дошёл до 2 039 808 переходов
(включая warmup), 1 154 секунды обучения. Независимая оценка на 50 seeds дала
0/50 успехов. Это отрицательный результат; конфигурация не является готовым
рецептом эксперта. Лог и метаданные — `evidence/ppo_place_v1_pilot.json`.
После выявленного дефекта награда исправлена, но это не делает старые веса
успешными и не доказывает сходимость исправленной версии.

Ограниченный пилот **исправленной версии v2**: reach 32 768 → lift +303 104 →
place +507 904 перехода (всего 843 776); последние две стадии заняли 148 и 303
секунды. На 20 новых seeds — 0/20 успехов. Это существенно меньший бюджет, чем
у старого place-пилота, поэтому сравнение не является абляцией награды.
Доказательства — `evidence/ppo_curriculum_v2_pilot.json`. Исправление reward
проверено контрпримером, однако стартовый PPO-рецепт ещё не откалиброван по
успешности. Эти веса не выдаются за эксперта и не входят в студенческий ZIP.

**Полная сходимость восьми RL-экспертов и качество BC после полномасштабного
обучения пока не подтверждены.** Физический контроллер доказывает выполнимость
сцен, но не доступность решения PPO в ограниченный учебный бюджет. Скрытый probe
проверен на трёх вариантах каждой задачи, не на всём диапазоне генератора.

До выдачи студентам организаторам нужно провести полный учебный пилот, подобрать
при необходимости reward/curriculum, зафиксировать бюджеты и пороги успешности.
Не объявлять проект откалиброванным по времени или RL-успеху только на основании
успешных unit-тестов. Команда запуска матрицы пилотов — в `reviewer/README.md`.

## Воспроизведение инженерных проверок

```bash
MUJOCO_GL=osmesa python -m pytest -q
MUJOCO_GL=osmesa python -m reviewer.check_scenes --out runs/physical_checks.json
MUJOCO_GL=osmesa python -m reviewer.smoke_matrix --out runs/integration_new
python -m reviewer.export_students dist/physical-ai-student --zip
```

Новые output-каталоги обязательны: обучение/сбор не перезаписывают предыдущие
артефакты молча. Файлы из `evidence/` не включаются в студенческий экспорт.
