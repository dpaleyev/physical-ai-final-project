# Фактическая валидация

Дата: 2026-09-29. Хост: Linux x86_64, Python 3.12.3, 24 логических CPU, 61 GiB RAM.
Рабочий NVIDIA-драйвер недоступен. MuJoCo 3.3.7, PyTorch 2.7.1+cpu; рендер OSMesa.
Полный список версий — `requirements-lock.txt`.

## Подтверждено

- Все восемь сохранённых XML компилируются после переноса вместе с assets.
  В каждом есть `home` keyframe с настроенной позой руки и открытым захватом.
- 26 автоматических тестов проходят локально и в Docker с чистой установкой
  зависимостей. Запуск Docker-тестов выполнялся без сети. Лог — `evidence/test_results.txt`.
- Физический probe выполнил **24/24 base-эпизода** (3 seeds на каждую из 8 пар)
  и **8/8 advanced-эпизодов** (один вариант на пару). Каждый уложился в 1000
  управляющих шагов. Подробные позиции, цели, heights и steps —
  `evidence/physical_probes.json`.
- Пробой используются настоящие контакты, приводы и трение; нет weld-приклеивания
  или переноса предметов через запись qpos во время эпизода.
- Сквозной smoke: настоящие PPO-обновления для 8 пар → сбор эпизодов → обучение
  трёх BC-вариантов → TorchScript → приватная оценка. **64/64 конфигурации
  оценщика без технической ошибки**. Доказательства — `evidence/integration_smoke.json`.
- PPO resume проверен с изменением размера rollout, seed и числа сред (1 → 2).
- Экспорт исключает приватные файлы и историю; в студенческом экспорте отдельно
  прошли 20 публичных тестов. Финальный Docker-образ проверен без bind-mount и сети.
- Независимое ревью выявило три ошибки (ориентации MJCF, параметры resume,
  изоляция ошибки отсутствующего артефакта). Для каждой воспроизведено падение
  regression-теста; исправления прошли полную suite.

## Что эти проверки не доказывают

Smoke использует 64 PPO-шага на пару, четыре перехода в демонстрации, одну эпоху
BC и два шага при проверке интерфейса оценщика. Эти данные намеренно включают
неуспешные эпизоды. Полученные веса не являются готовыми экспертами или учебными
результатами и не включаются в студенческую поставку.

Отдельный PPO-пилот на UR5e/cup_plate выполнил 32 768 шагов стадии `reach`, примерно
2 200 transitions/s на восьми CPU-процессах. На трёх проверочных эпизодах полная
задача не решена (0/3). Это короткая проверка обучения, не оценка финального метода.
Метаданные и результаты — `evidence/ppo_short_pilot.json`.

**Полная сходимость восьми RL-экспертов и качество BC после полномасштабного
обучения пока не подтверждены.** Физический контроллер доказывает выполнимость
сцен, но не доступность решения PPO в ограниченный учебный бюджет. Скрытый probe
проверен на одном варианте каждой задачи, не на всём диапазоне генератора.

До выдачи студентам организаторам нужно провести полный учебный пилот, подобрать
при необходимости reward/curriculum, зафиксировать бюджеты и пороги успешности.
Не объявлять проект откалиброванным по времени или RL-успеху только на основании
успешных unit-тестов. Команда запуска матрицы пилотов — в `reviewer/README.md`.

## Воспроизведение инженерных проверок

```bash
MUJOCO_GL=osmesa python -m pytest -q
MUJOCO_GL=osmesa python -m reviewer.smoke_matrix --out runs/integration_new
python -m reviewer.export_students dist/physical-ai-student --zip
```

Новые output-каталоги обязательны: обучение/сбор не перезаписывают предыдущие
артефакты молча. Файлы из `evidence/` не включаются в студенческий экспорт.
